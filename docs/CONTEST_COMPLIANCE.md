## 提交前必须由团队补齐的材料

比赛要求中的以下内容属于团队信息或运营材料，不能由代码仓库自动生成：

1. 团队名称、成员姓名、学院、年级和联系方式；
2. 作品名称、简介、目标用户和应用场景；
3. 公开体验链接或二维码，并确认评审期间持续可访问；
4. 实际使用的大模型/API/平台说明；默认 deterministic 模式不产生外部 API 费用；
5. 费用说明及订单、支付记录或平台账单（如有）；
6. 完整知识库来源清单，补充每个公开网页/公众号的原始链接；
7. 作品使用说明、演示截图或视频；
8. 学生试用反馈和改进记录。

## 合规注意事项

- 不要把 `规章制度.zip` 原始附件、API Key、`.env`、数据库密码、学号或其他个人隐私提交到 GitHub。
- 当前仓库只提交经核验的结构化公开资料快照；原始资料包通过指纹登记，便于审计但不公开附件。
- Docker Compose 中的密码仅用于本地演示，正式部署前必须替换，并设置 `ADMIN_API_KEY`。
- 默认 Agent provider 为 deterministic，便于零费用稳定演示；使用真实模型时应如实填写模型和 API 费用。
- 回答页面已展示“非学校官方系统”及“以最新正式通知为准”的边界提示。

## 快速验收

Windows 安装并启动 Docker Desktop 后，双击 `quick_start.cmd`，确认以下地址均可访问：

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/docs`
- `http://127.0.0.1:8000/api/health`
- `http://127.0.0.1:8000/api/ready`

停止服务双击 `stop_services.cmd`。提交前运行 `python -m pytest -q`，并保留测试结果截图或日志。
